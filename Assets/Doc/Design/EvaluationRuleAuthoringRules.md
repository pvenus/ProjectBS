# 평가 룰 작성 룰

- formatId: `design.rule.evaluation_rule_authoring`
- version: `1`

## 목적

문서, 데이터, 콘텐츠, 기획 결과물 또는 구현 결과물을 평가하는 새로운 평가 룰을 작성할 때 따라야 하는 공통 기준을 정의한다.

이 문서는 개별 결과물을 직접 평가하지 않는다. 개별 평가에 사용할 평가 항목, 배점, 감점, 절대 탈락 기준과 결과 보고 형식을 설계하는 메타 룰이다.

## 필수 평가 원칙

모든 평가 룰은 다음 조건을 반드시 따른다.

1. 평가는 100점 만점이다.
2. 최종 점수가 80점 이하이면 탈락이다.
3. 최종 점수가 81점 이상이면 점수 기준을 통과한다.
4. 평가 대상에 따라 절대 탈락 기준을 둘 수 있다.
5. 절대 탈락 기준에 해당하면 점수와 관계없이 탈락한다.

```text
점수 통과: 81~100점
점수 탈락: 0~80점
절대 탈락: 점수와 관계없이 탈락
```

## 평가 룰 문서의 필수 구조

새로운 평가 룰 문서는 최소한 다음 항목을 포함해야 한다.

1. 목적
2. 평가 대상
3. 평가 기준이 되는 원본 또는 기준 문서
4. 평가 영역과 영역별 배점
5. 세부 평가 항목
6. 감점 기준
7. 절대 탈락 기준
8. 중복 감점 처리 기준
9. 평가 절차
10. 최종 점수 계산 방식
11. 통과 및 탈락 판정 방식
12. 결과 보고 형식
13. 평가 체크리스트

필요한 경우 허용되는 차이, 평가 제외 대상, 등급, 영역별 최저점 또는 점수 상한을 추가할 수 있다.

## 평가 기준의 우선순위

평가 룰은 무엇을 정답으로 간주하는지 먼저 명시해야 한다.

기준이 여러 개라면 적용 우선순위를 작성한다.

예:

1. 사용자가 확정한 요구사항
2. 원본 데이터 또는 원본 문서
3. 프로젝트 공통 디자인 룰
4. 대상 파일의 포맷 규칙
5. 파생 기획 데이터와 참고 문서

하위 기준이 상위 기준과 충돌하면 상위 기준을 적용한다.

기준이 불명확하여 객관적으로 판정할 수 없는 항목은 임의로 감점하지 않는다. 해당 항목은 `판정 불가`로 기록하고 필요한 기준을 함께 보고한다.

## 배점 설계 규칙

### 총점

모든 평가 영역의 배점 합계는 정확히 100점이어야 한다.

```text
영역 1 + 영역 2 + ... + 영역 N = 100점
```

합계가 100점이 아니면 평가 룰 자체가 유효하지 않다.

### 영역 구성

평가 영역은 서로 다른 품질 특성을 측정하도록 나눈다.

좋은 영역 예:

- 원본 보존
- 기능 정확성
- 데이터 구조
- 사용자 흐름
- 안정성

피해야 할 영역 예:

- 정확성
- 올바름
- 문제없음

서로 같은 의미를 반복하는 영역을 만들지 않는다.

### 중요도 반영

배점은 항목 수가 아니라 중요도에 따라 정한다.

- 핵심 목적과 직접 연결된 영역은 높은 배점을 준다.
- 형식, 표현, 정리 상태처럼 보조적인 영역은 핵심 기능보다 낮은 배점을 준다.
- 한 영역에 전체 점수가 과도하게 몰리지 않도록 하되, 실제 중요도가 높다면 이유를 명시한다.
- 절대 탈락 기준으로 처리할 항목을 점수 감점만으로 약하게 평가하지 않는다.

### 영역별 최대 감점

각 영역의 감점 합계는 해당 영역의 배점을 넘을 수 없다.

예:

```text
선택지 정확성 배점: 30점
선택지 관련 오류 감점 합계: 최대 30점
```

최종 점수는 0점보다 낮아질 수 없다.

## 세부 평가 항목 작성 규칙

각 평가 항목에는 다음 내용을 명시한다.

- 검사 대상
- 통과 조건
- 실패 조건
- 오류 코드
- 건당 감점 또는 조건별 감점
- 영역 최대 감점
- 필요한 경우 오류 예시

권장 형식:

| 검사 항목 | 통과 조건 | 오류 코드 | 감점 |
|---|---|---|---:|
| 항목 이름 | 객관적으로 확인 가능한 조건 | `ERROR_CODE` | -N |

통과 조건은 평가자에 따라 해석이 달라지지 않도록 구체적으로 작성한다.

나쁜 예:

```text
내용이 자연스러우면 통과한다.
```

좋은 예:

```text
원본의 모든 선택지가 동일한 문구와 순서로 존재해야 한다.
```

## 감점 설계 규칙

### 감점 방식

평가는 100점에서 오류별 점수를 차감하는 방식으로 계산한다.

```text
최종 점수 = 100 - 적용된 모든 감점
```

오류의 영향에 따라 감점 크기를 구분한다.

| 오류 심각도 | 권장 감점 | 의미 |
|---|---:|---|
| 경미 | -1~-3 | 표현, 메타데이터 또는 작은 형식 오류 |
| 보통 | -4~-7 | 일부 기능이나 의미에 영향을 주는 오류 |
| 중대 | -8~-15 | 핵심 데이터 누락, 잘못된 동작 또는 구조 변경 |
| 치명적 | 절대 탈락 검토 | 평가 목적 자체를 충족하지 못함 |

권장 범위는 강제값이 아니다. 평가 대상에 맞게 조정할 수 있지만 감점 크기의 이유가 일관되어야 한다.

### 중복 감점 금지

하나의 원인에서 파생된 동일한 오류를 여러 필드나 파일에서 발견해도 원칙적으로 한 번만 감점한다.

오류 적용 우선순위:

1. 추가 또는 누락
2. 잘못된 값 또는 의미 변경
3. 위치 또는 연결 오류
4. 개수 불일치
5. 파생 데이터 충돌

예:

```text
원본에 없는 선택지가 추가됨
→ CHOICE_ADDED만 적용
→ 해당 선택지에 원본 문구가 없다는 이유로 CHOICE_TEXT_MISMATCH를 중복 적용하지 않음
```

단, 하나의 문제가 서로 다른 품질 영역에 독립적인 피해를 발생시켰다면 영역별 감점이 가능하다. 이 경우 왜 별도 감점인지 결과에 설명해야 한다.

### 건수 계산

평가 룰은 오류 한 건의 단위를 명확히 정의해야 한다.

가능한 단위:

- 파일 하나
- 문장 하나
- 선택지 하나
- 전투 하나
- 필드 하나
- 연결 하나
- 동일 원인의 오류 묶음 하나

글자 하나마다 감점하는 것처럼 지나치게 세분화된 계산은 피한다.

## 절대 탈락 기준 작성 규칙

### 의미

절대 탈락은 최종 점수가 81점 이상이어도 평가를 탈락시키는 기준이다.

다음과 같은 경우에만 사용한다.

- 평가 목적 자체를 충족하지 못한 경우
- 안전, 보안, 법적 요구사항을 위반한 경우
- 필수 데이터나 핵심 기능이 완전히 빠진 경우
- 원본 또는 요구사항과 정반대의 결과가 만들어진 경우
- 결과물을 정상적으로 사용하거나 검증할 수 없는 경우

단순 오탈자, 경미한 형식 차이, 작은 메타데이터 오류를 절대 탈락으로 만들지 않는다.

### 작성 조건

각 절대 탈락 기준에는 다음 내용을 명시한다.

- 기준 ID
- 검사 대상
- 탈락 조건
- 탈락시키는 이유
- 대표 예시
- 해당하지 않는 예외

권장 형식:

| 기준 ID | 절대 탈락 조건 | 이유 |
|---|---|---|
| `AF-01` | 필수 원본 파일을 확인할 수 없음 | 평가 근거가 없어 결과 신뢰 불가 |

### 적용 우선순위

절대 탈락 여부를 점수 계산보다 먼저 확인한다.

절대 탈락이 발견되어도 가능한 범위에서 점수 계산을 계속하여 결과에 함께 기록한다. 다만 최종 판정은 반드시 `FAIL_ABSOLUTE`로 표시한다.

```text
Score: 92/100
Result: FAIL_ABSOLUTE
Absolute failure: AF-02
```

절대 탈락 기준이 없는 평가라면 문서에 다음처럼 명시한다.

```text
절대 탈락 기준: 없음
```

## 점수 상한 규칙

필요한 경우 특정 중대 오류에 점수 상한을 적용할 수 있다.

예:

```text
핵심 기능 누락이 있으면 감점 계산 결과와 관계없이 최고 점수는 80점이다.
```

점수 상한은 절대 탈락과 다르다.

- 점수 상한: 계산된 점수를 제한하여 점수 기준으로 탈락시킨다.
- 절대 탈락: 계산 점수와 관계없이 탈락시킨다.

같은 오류에 점수 상한과 절대 탈락을 동시에 적용하지 않는다. 더 강한 기준인 절대 탈락만 적용한다.

## 평가 절차 작성 규칙

개별 평가 룰은 다음 순서로 평가하도록 작성한다.

1. 평가 대상과 기준 자료를 확인한다.
2. 평가에 필요한 파일 또는 데이터가 모두 있는지 확인한다.
3. 절대 탈락 기준을 먼저 검사한다.
4. 평가 영역별로 통과 및 오류 항목을 기록한다.
5. 같은 원인의 중복 감점을 제거한다.
6. 영역별 감점을 배점 한도 안에서 합산한다.
7. 100점에서 전체 감점을 차감한다.
8. 필요한 경우 점수 상한을 적용한다.
9. 80점 이하인지 확인한다.
10. 절대 탈락 여부를 최종 판정에 우선 적용한다.
11. 점수, 판정, 오류와 개선 항목을 보고한다.

## 최종 판정 규칙

최종 판정은 다음 세 값 중 하나를 사용한다.

| 판정 | 조건 |
|---|---|
| `PASS` | 절대 탈락이 없고 최종 점수가 81~100점 |
| `FAIL_SCORE` | 절대 탈락은 없지만 최종 점수가 0~80점 |
| `FAIL_ABSOLUTE` | 절대 탈락 기준에 하나 이상 해당 |

판정 순서:

```text
절대 탈락인가?
├─ 예 → FAIL_ABSOLUTE
└─ 아니오 → 최종 점수가 80점 이하인가?
   ├─ 예 → FAIL_SCORE
   └─ 아니오 → PASS
```

## 선택적 등급 규칙

평가 룰에 필요하다면 통과와 별도로 등급을 표시할 수 있다.

권장 등급:

| 점수 | 등급 |
|---|---|
| 95~100 | S |
| 90~94 | A |
| 85~89 | B |
| 81~84 | C |
| 70~80 | D |
| 0~69 | F |

등급은 품질 수준을 나타내며 통과 판정을 대체하지 않는다. 절대 탈락 대상도 계산 점수에 따른 등급은 기록할 수 있지만 결과는 `FAIL_ABSOLUTE`다.

## 결과 보고 형식

모든 평가 룰은 최소한 다음 결과를 출력하도록 작성한다.

```text
Evaluation:
Target:
Reference:

Score: 0~100/100
Result: PASS | FAIL_SCORE | FAIL_ABSOLUTE
Grade: S | A | B | C | D | F | not_used

Absolute failures:
- none

Score breakdown:
- Evaluation area 1: 0~N/N
- Evaluation area 2: 0~N/N

Errors:
- Code:
  Deduction:
  Location:
  Expected:
  Actual:
  Reason:

Allowed differences:
- none

Required fixes:
1. 가장 먼저 고쳐야 할 항목
```

결과 보고 시 다음 원칙을 지킨다.

- 점수와 판정을 모두 기록한다.
- 절대 탈락 사유를 일반 감점 오류와 구분한다.
- 각 감점의 근거와 위치를 기록한다.
- 영역별 획득 점수와 배점을 기록한다.
- 허용된 차이는 오류 목록에 넣지 않는다.
- 수정 우선순위는 절대 탈락, 중대 오류, 보통 오류, 경미한 오류 순서로 작성한다.

## 평가 룰 자체 검증

새 평가 룰을 완성한 뒤 해당 룰이 다음 조건을 만족하는지 확인한다.

- 평가 목적과 대상이 구체적인가?
- 무엇을 정답으로 보는지 명시되어 있는가?
- 평가 영역 배점의 합이 정확히 100점인가?
- 81점 이상은 점수 기준 통과인가?
- 80점 이하는 점수 기준 탈락인가?
- 절대 탈락 기준의 유무가 명시되어 있는가?
- 절대 탈락이 점수 판정보다 우선하는가?
- 세부 항목에 객관적인 통과 및 실패 조건이 있는가?
- 오류 코드와 감점이 정의되어 있는가?
- 같은 원인의 중복 감점을 방지하는 규칙이 있는가?
- 영역 감점이 영역 배점을 넘지 않는가?
- 최종 점수가 0점보다 낮아지지 않는가?
- 점수 상한과 절대 탈락을 혼동하지 않았는가?
- 결과 보고 형식에 점수, 판정, 영역별 점수와 오류 근거가 포함되는가?

하나라도 충족하지 못하면 해당 평가 룰은 사용 전에 수정해야 한다.
