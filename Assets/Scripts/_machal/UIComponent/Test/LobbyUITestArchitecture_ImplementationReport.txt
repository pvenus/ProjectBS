# 개요
이번 작업의 목적:
- Lobby UI 로직을 도메인 로직과 완벽히 분리하고, 모듈식 테스트가 가능한 Sandbox 환경을 구축한다.
- Static Action(이벤트 버스) 기반의 강결합 라우팅을 폐기하고, Manager Proxy 패턴 (IShopManager 등)을 도입하여 테스트/런타임 호환성을 극대화한다.
- UI 에셋 인스턴스화, 텍스트 현지화(StringManager), 에디터 Play 모드 진입 시 발생하는 각종 버그 및 예외를 수정한다.

# 주요 클래스 설명
LobbyTestFlowController
- 테스트 환경에서 `EventPopupChoiceData`의 ActionType에 따라 적절한 Manager 인터페이스의 메서드를 호출(라우팅)하는 역할

TestShopManager
- `IShopManager` 인터페이스의 테스트 전용 구현체. 지정된 `ShopItemPoolSO`에서 랜덤으로 아이템을 추출하여 상점 페이지에 Mock 런타임 데이터를 주입함.

PlayModeSelectionClearer
- 유니티 에디터 Play 모드 진입 시 Hierarchy 선택을 자동으로 해제하여, 인스펙터의 파괴된 객체 참조 에러(SerializedObjectNotCreatableException)를 원천 차단함.

EventPopupView & ShopPage
- 뷰(View) 계층. 어떠한 도메인 매니저도 직접 참조하지 않으며, 오로지 `Show(Data, Callback)` 형태로 데이터를 주입받아 화면에 그리고 클릭 시 콜백만 반환함.

# 에디터 작업
처음부터 테스트 씬을 구성하는 절차:
1. 유니티 상단 메뉴 Tools -> UI -> Create Lobby UI Test Scene 클릭 (씬 생성 및 CoreManagers 자동 추가됨)
2. Hierarchy에서 `LobbyUITestRunner / EventPopupTestScenario` 선택
3. Event Popup Prefab 슬롯에 `UI_EventPopup` 프리팹 할당
4. Hierarchy에서 `LobbyUITestRunner / TestShopManager` 선택
5. Shop Page Prefab 슬롯에 `UI_ShopNormal` 프리팹 할당
6. Mock Shop Pools 슬롯들에 각각 알맞은 `ShopItemPoolSO` (유물, 전술, 소모품 풀) 할당
7. 씬 저장 (Ctrl + S)

---

# 테스트 방법
1. 유니티 Editor에서 씬 저장 후 Play(▶) 실행
2. 화면 우측 Test Panel에서 'Shop Event Popup' 버튼 클릭
3. 생성된 이벤트 팝업 UI에서 '물건을 본다' 버튼 클릭
4. 콘솔 로그 출력과 함께 상점 UI가 열리고, 설정한 Pool 데이터 기반으로 상품이 카테고리별로 배치되어 있는지 확인
5. 아이템의 Buy 버튼을 눌렀을 때 콘솔에 클릭 로그와 구매 처리 로직이 동작하는지 확인

# 실제 런타임 연결 시 변경 사항
현재 구조:
UI 내부 로직은 철저하게 `IShopManager` 등 인터페이스만 바라보고 있으며, `LobbyTestFlowController`가 `TestShopManager`를 주입해 동작함.

실제 런타임:
동일하게 UI 코드는 단 1줄도 수정할 필요가 없음. 실제 씬의 게임 컨트롤러(예: LobbyMapController)에서 `TestShopManager` 대신 실제 `ShopManager` 구현체를 UI로 주입(Inject)해주기만 하면 완벽히 실제 흐름으로 전환됨.
