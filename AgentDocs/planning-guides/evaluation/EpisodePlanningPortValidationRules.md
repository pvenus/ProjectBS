# 에피소드 기획 데이터 포팅 검증 룰

- formatId: `design.rule.episode_planning_port_validation`
- version: `4`

## 목적

`AgentDocs/planning-data/story`의 Episode MD를 `AgentDocs/planning-data/story-planning`의 Episode Planning JSON으로 포팅할 때 원본 스토리, 선택지, 전투 여부가 임의로 바뀌지 않았는지 평가한다.

이 문서는 새로운 스토리를 작성하는 규칙이 아니다. 이미 작성된 Episode MD를 실데이터로 옮긴 결과가 원본과 같은 의미와 진행 구조를 보존하는지 검증하는 규칙이다.

## 적용 대상

다음 두 파일을 한 쌍으로 비교한다.

- 원본: `common.source.sourceEpisodeFile`이 가리키는 Episode MD
- 포팅 결과: 해당 `episode.*.json`

Chapter 요약, `sceneBeats`, `episodeSummary`, 기획 메모는 보조 자료로만 사용한다. 원본 Episode MD가 지문, 선택지, 전투 여부의 기준 데이터다.

## 핵심 원칙

포팅은 원본의 재창작이 아니라 구조화다.

- 원본 지문을 고쳐 쓰거나 요약하거나 보충하지 않는다.
- 원본에 없는 선택지를 새로 만들지 않는다.
- 원본에 있는 선택지를 삭제하거나 둘로 나누거나 합치지 않는다.
- `[전투]` 표기가 있는 장면만 전투 데이터로 만든다.
- `[전투]` 표기가 없는 장면에는 전투 데이터나 전투 진입 선택지를 만들지 않는다.
- 원본의 사건 순서와 선택지 위치를 유지한다.
- 줄바꿈과 popup 분할은 표시 목적에 따라 조정할 수 있다.

## 빠른 판정표

| 검사 대상 | 통과 조건 | 대표 오류 |
|---|---|---|
| 지문 | 줄바꿈을 제외한 문구와 의미 태그가 원본과 같다. | `NARRATION_TEXT_MISMATCH` |
| 선택지 | 원본의 `선택:` 문장과 JSON 선택지가 문구·개수·순서·위치·목적지까지 일대일로 같다. | `CHOICE_ADDED`, `CHOICE_MISSING`, `CHOICE_TEXT_MISMATCH`, `CHOICE_FLOW_MISMATCH` |
| 전투 | 원본의 `[전투]` 또는 `[전투][전직보상]`과 JSON battle이 개수·위치·보상 의미까지 일대일로 같다. | `BATTLE_WITHOUT_SOURCE_TAG`, `BATTLE_MISSING`, `BATTLE_POSITION_MISMATCH` |
| 전개 | popup 분할 뒤에도 사건, 선택, 전투, 이동의 상대 순서가 같다. | `STORY_FLOW_CHANGED` |
| 파생 데이터 | 요약과 기획 필드가 원본을 보충하거나 반박하지 않는다. | `DERIVED_DATA_CONTRADICTS_SOURCE` |

판정 우선순위는 다음과 같다.

1. 원본 Episode MD
2. 원문 보존 필드인 `originalTextKo`
3. 실제 표시 필드인 `displayTextKo`
4. 선택지와 popup 연결 데이터
5. battle, reward, handoff 및 Chapter 단위 기획 데이터
6. 요약, 방향성, 메모 등 파생 데이터

하위 순위 데이터가 상위 순위 데이터와 충돌하면 상위 순위를 기준으로 오류를 판정한다.

## 지문 보존 규칙

### 원문 필드

다음 필드는 원본 Episode MD의 플레이어 노출 본문을 보존해야 한다.

- `story.sourceNarration.blocks[].originalTextKo`
- `story.popupDefinitions[].originalTextKo`

두 필드에 저장된 전체 문장을 `sourceParagraphOrder` 또는 `popupOrder` 순서로 이어 붙였을 때 원본 본문과 같아야 한다.

### 허용되는 차이

다음 차이는 지문 변경으로 판정하지 않는다.

- CRLF와 LF의 차이
- 문단 사이 빈 줄 개수
- popup 분할을 위한 줄바꿈 추가 또는 제거
- JSON escape 표현
- 파일 끝 개행 유무
- 제목과 Episode 기능 요약을 별도 필드로 옮긴 결과

`displayTextKo`는 화면 배치를 위해 문단을 합치거나 나눌 수 있다. 단, 줄바꿈을 제외한 실제 문구는 원본과 같아야 한다.

### 허용되지 않는 차이

다음 중 하나라도 있으면 `NARRATION_TEXT_MISMATCH` 오류로 판정한다.

- 단어, 조사, 문장부호의 변경
- 문장 누락 또는 추가
- 문장 순서 변경
- 원본 문장의 요약 또는 의역
- 원본에 없는 상황, 감정, 행동의 보충
- `[전투]`, `[전직보상]`, `선택:` 같은 의미 태그의 삭제 또는 변경

태그는 공백이나 줄바꿈이 아니라 의미 데이터이므로 그대로 보존해야 한다.

```text
원본: [전투][전직보상] 숲속 오두막의 추격자
오류: [전투] 숲속 오두막의 추격자
```

## 선택지 원문 일치 규칙

### 선택지의 기준

원본 Episode MD에서 `선택:`으로 명시된 문장만 포팅 선택지가 될 수 있다.

JSON의 다음 선택지 문구는 원본의 `선택:` 뒤 행동 문장과 글자 단위로 같아야 한다.

- `story.choiceDirections[].sourceChoiceText`
- `story.popupDefinitions[].choices[].sourceChoiceText`

비교할 때 원본의 `선택:` 접두어와 그 뒤 한 칸은 구조 표기이므로 제외할 수 있다. 행동 문장 자체는 바꾸지 않는다.

### 선택지 일대일 대응

원본 선택지와 JSON 선택지는 다음 조건을 모두 만족해야 한다.

1. 원본 선택지 하나는 JSON의 의미상 선택지 하나와 대응한다.
2. JSON의 모든 선택지는 원본에서 동일한 문구를 찾을 수 있어야 한다.
3. 원본의 모든 선택지는 JSON에 존재해야 한다.
4. 같은 선택지를 `choiceDirections`와 `popupDefinitions`에 각각 표현한 것은 중복으로 세지 않는다.
5. 원본에서 선택지가 위치한 사건 또는 지문 뒤에 대응 popup 선택지를 배치한다.
6. 원본 선택지의 순서와 분기 목적지를 유지한다.

### 금지 사항

- 지문에서 가능한 행동을 추론하여 선택지로 추가하지 않는다.
- `sceneBeats`, `episodeSummary`, `displayDirective`에서 선택지를 새로 만들지 않는다.
- 강제 진행 문장을 선택지로 바꾸지 않는다.
- 하나뿐인 진행 행동을 임의의 두 선택지로 확장하지 않는다.
- 선택지 표현을 더 짧거나 자연스럽게 다듬지 않는다.
- 서로 다른 원본 선택지를 같은 `choiceId` 또는 같은 분기 결과로 잘못 합치지 않는다.

다음은 모두 오류다.

```text
원본에 없음
JSON 선택지: 남은 흔적을 확인한다.
JSON 선택지: 실종자 가족에게 묻는다.
```

원본에 없는 선택지가 있으면 `CHOICE_ADDED` 오류로 판정한다. 원본 선택지가 빠졌으면 `CHOICE_MISSING`, 문구가 달라졌으면 `CHOICE_TEXT_MISMATCH`, 위치나 목적지가 달라졌으면 `CHOICE_FLOW_MISMATCH`로 판정한다.

## 전투 표식 일치 규칙

### 전투 판정의 유일한 기준

Episode MD의 다음 표기만 실제 전투의 근거로 인정한다.

```text
[전투] 전투 제목
[전투][전직보상] 전투 제목
```

`[전투][전직보상]`도 전투 1개로 센다. `[전직보상]`은 해당 전투의 추가 보상 의미이며 삭제하거나 일반 `[전투]`로 바꾸지 않는다.

적, 무기, 위협, 추격, 대치, 돌진 같은 표현이 지문에 있더라도 `[전투]` 표기가 없으면 전투로 추론하지 않는다.

### 원본에 전투가 있는 경우

원본에 `[전투]` 또는 `[전투][전직보상]`이 있으면 JSON은 다음 조건을 모두 만족해야 한다.

- `battle.battleNeed`가 전투 필요 상태다.
- 해당 전투와 연결되는 전투 선택지만 `opens: ["battle"]` 또는 이에 준하는 전투 진입값을 가진다.
- `handoff.battleStoryContextCandidateId`, `battleJsonRef` 등 전투 참조가 해당 전투와 대응한다.
- Chapter 전투 계획과 몬스터 풀에 해당 Episode 전투가 존재한다.
- 전투 제목, 전투 위치, 전투 진입 선택지가 원본과 대응한다.
- `[전직보상]`이 있으면 보상 기획에도 전직 보상 의미가 보존된다.

원본에 전투가 있는데 JSON 전투 데이터가 없으면 `BATTLE_MISSING` 오류다.

### 원본에 전투가 없는 경우

원본에 `[전투]`와 `[전투][전직보상]`이 모두 없으면 JSON은 다음 조건을 만족해야 한다.

- `battle.battleNeed`가 전투 없음 상태다.
- 어떤 선택지도 `battle`을 열지 않는다.
- 해당 Episode용 `battleStoryContextCandidateId`와 `battleJsonRef`를 만들지 않는다.
- Chapter 전투 계획에 해당 Episode 전투를 넣지 않는다.
- 보상을 전투 클리어 보상으로 설정하지 않는다.
- 적이나 위험 묘사를 근거로 전투를 임의 생성하지 않는다.

원본에 전투 표식이 없는데 하나라도 전투 데이터가 있으면 `BATTLE_WITHOUT_SOURCE_TAG` 오류다.

### 전투 개수와 위치

- 원본의 전투 표식 개수와 JSON에서 진입 가능한 전투 개수는 같아야 한다.
- 전투는 원본에서 해당 `[전투]` 표식이 놓인 지점 이후에 진입해야 한다.
- 조사 선택지나 동료 합류 선택지를 전투 선택지로 바꾸지 않는다.
- 원본의 전투 선택지를 다른 popup으로 옮겨 사건 순서를 바꾸지 않는다.

개수가 다르면 `BATTLE_COUNT_MISMATCH`, 위치가 달라지면 `BATTLE_POSITION_MISMATCH` 오류로 판정한다.

## 전개 순서 보존 규칙

원본 본문을 위에서 아래로 읽었을 때의 사건 순서를 유지한다.

다음 요소의 상대 순서가 같아야 한다.

1. 장소와 상황 제시
2. 인물 또는 단서 등장
3. 선택지 제시
4. 선택 결과 문장
5. 전투 표식과 전투 진입
6. 다음 장소 또는 다음 Episode로의 이동

popup을 합치거나 나누는 것은 허용하지만, 분할 때문에 뒤 문장이 먼저 표시되거나 선택지가 원래보다 일찍 열리면 안 된다.

원본에 없는 분기, 우회 경로, 조기 전투, 추가 합류 결정을 만들면 `STORY_FLOW_CHANGED` 오류로 판정한다.

## 파생 기획 필드 규칙

다음 필드는 원문을 요약하거나 구조화한 파생 데이터이므로 원문과 글자 단위로 같을 필요는 없다.

- `episodeSummary`
- `sceneBeats`
- `emotionalTone`
- `mustShow`
- `mustHide`
- `displayDirective`
- `choiceIntent`
- `outcomeDirection`
- `monster`
- `battle`
- `reward`
- `handoff`
- `constraints`
- `notes`

다만 파생 필드가 원문에 없는 사건, 선택지, 전투, 보상 또는 확정 사실을 새로 만들면 안 된다. 파생 필드와 원문이 충돌할 경우 원본 Episode MD를 우선하며 `DERIVED_DATA_CONTRADICTS_SOURCE` 오류로 판정한다.

## 평가 절차

Episode 하나마다 다음 순서로 평가한다.

1. `sourceEpisodeFile`이 실제 원본 Episode를 가리키는지 확인한다.
2. 원본에서 제목, 기능 요약, 플레이어 노출 본문을 구분한다.
3. 줄바꿈을 제외하고 원본 본문과 `originalTextKo` 및 `displayTextKo`의 문구를 비교한다.
4. 원본의 모든 `선택:` 문장을 순서대로 추출한다.
5. JSON의 의미상 선택지와 원본 선택지를 일대일 비교한다.
6. 원본의 `[전투]` 및 `[전투][전직보상]` 개수와 위치를 추출한다.
7. Episode JSON, Chapter 전투 계획, 전투 참조 데이터의 전투 개수와 위치를 비교한다.
8. popup 순서, `nextPopupId`, 선택지 목적지가 원본 전개 순서를 보존하는지 확인한다.
9. 발견한 차이를 오류 코드와 원본/JSON 위치를 포함해 보고한다.
10. 아래 배점표에 따라 감점하고 100점 만점의 최종 점수를 계산한다.

평가는 다음 네 단계로 묶어 수행한다.

| 단계 | 검사 내용 | 배점 |
|---|---|---:|
| 1. 원문 검사 | 지문과 의미 태그 | 30점 |
| 2. 구조 검사 | 선택지의 문구, 개수, 위치와 목적지 | 30점 |
| 3. 전투 검사 | 전투 표식, battle, 보상과 참조 | 30점 |
| 4. 흐름 검사 | 사건 순서, popup 연결과 파생 데이터 | 10점 |

## 100점 평가 기준

### 기본 계산 원칙

모든 Episode는 100점에서 시작한다.

```text
최종 점수 = 100 - 지문 보존 감점 - 선택지 감점 - 전투 감점 - 전개 및 파생 데이터 감점
```

- 최종 점수는 0점보다 낮아질 수 없다.
- 소수점은 사용하지 않고 정수로 기록한다.
- 같은 원인에서 파생된 동일 오류를 여러 JSON 필드에서 발견해도 한 번만 감점한다.
- 같은 선택지가 `choiceDirections`와 `popupDefinitions` 양쪽에 잘못 들어간 경우 선택지 하나의 오류로 센다.
- 하나의 문제가 서로 다른 평가 영역을 실제로 훼손했다면 각 영역에서 감점할 수 있다.
- 각 영역의 감점은 해당 영역의 최대 배점을 넘을 수 없다.
- 줄바꿈, 빈 줄, popup 분할처럼 명시적으로 허용된 차이는 감점하지 않는다.

### 감점 적용 우선순위

한 문제가 여러 오류처럼 보일 때는 가장 직접적인 원인 하나를 우선 적용한다.

1. 추가 또는 누락 오류
2. 문구 또는 의미 변경 오류
3. 위치 또는 목적지 오류
4. 개수 불일치 오류
5. 파생 데이터 충돌 오류

예를 들어 원본에 없는 선택지가 JSON에 추가되었다면 `CHOICE_ADDED`만 적용한다. 그 선택지에 원본 문구가 없다는 이유로 `CHOICE_TEXT_MISMATCH`를 함께 적용하지 않는다.

다만 서로 다른 평가 영역을 실제로 훼손한 경우에는 영역별로 감점한다. 예를 들어 `[전투][전직보상]`에서 `[전직보상]`을 삭제하고 보상 데이터도 일반 전투 보상으로 바꿨다면 지문 영역과 전투 영역에서 각각 감점한다.

### 영역별 배점

| 평가 영역 | 배점 |
|---|---:|
| 지문 및 의미 태그 보존 | 30점 |
| 선택지 원문 및 대응 보존 | 30점 |
| 전투 표식 및 battle 데이터 대응 | 30점 |
| 전개 순서 및 파생 데이터 정합성 | 10점 |
| 합계 | 100점 |

## 지문 및 의미 태그 보존: 30점

| 오류 | 오류 코드 | 건당 감점 | 영역 최대 감점 |
|---|---|---:|---:|
| 원본 문장 또는 의미 있는 구절 누락 | `NARRATION_TEXT_MISMATCH` | -10 | -30 |
| 원본에 없는 문장 또는 의미 있는 구절 추가 | `NARRATION_TEXT_MISMATCH` | -10 | -30 |
| 단어, 조사, 문장부호 변경 | `NARRATION_TEXT_MISMATCH` | -3 | -30 |
| 문장 순서 변경 | `NARRATION_TEXT_MISMATCH` | -5 | -30 |
| `[전투]`, `[전직보상]`, `선택:` 등 의미 태그 변경 또는 삭제 | `NARRATION_TEXT_MISMATCH` | -5 | -30 |
| `originalTextKo`와 `displayTextKo` 사이의 실제 문구 불일치 | `NARRATION_TEXT_MISMATCH` | -3 | -30 |

완전히 같은 문장 안에서 여러 글자가 연속으로 바뀐 경우 글자별로 세지 않고 한 건의 문구 변경으로 센다. 문장 전체가 누락되거나 추가된 경우에는 단어 변경 감점을 중복 적용하지 않는다.

## 선택지 원문 및 대응 보존: 30점

| 오류 | 오류 코드 | 건당 감점 | 영역 최대 감점 |
|---|---|---:|---:|
| 원본에 없는 선택지 추가 | `CHOICE_ADDED` | -8 | -30 |
| 원본 선택지 누락 | `CHOICE_MISSING` | -8 | -30 |
| 선택지 행동 문구 변경 | `CHOICE_TEXT_MISMATCH` | -5 | -30 |
| 선택지 위치 변경 | `CHOICE_FLOW_MISMATCH` | -5 | -30 |
| 선택지 목적지 또는 결과 변경 | `CHOICE_FLOW_MISMATCH` | -8 | -30 |
| 원본 선택지를 임의로 분할하거나 합침 | `CHOICE_FLOW_MISMATCH` | -8 | -30 |

선택지의 위치와 목적지가 모두 바뀌었다면 서로 다른 훼손이므로 각각 감점할 수 있다. 단, 원본에 전혀 없는 선택지는 `CHOICE_ADDED`만 적용하고 그 선택지의 문구·위치·목적지에 추가 감점하지 않는다.

## 전투 표식 및 battle 데이터 대응: 30점

| 오류 | 오류 코드 | 건당 감점 | 영역 최대 감점 |
|---|---|---:|---:|
| 전투 표식이 없는데 battle 생성 | `BATTLE_WITHOUT_SOURCE_TAG` | -15 | -30 |
| 전투 표식이 있는데 battle 누락 | `BATTLE_MISSING` | -15 | -30 |
| 원본과 전투 개수 불일치 | `BATTLE_COUNT_MISMATCH` | -10 | -30 |
| 전투 진입 위치 변경 | `BATTLE_POSITION_MISMATCH` | -8 | -30 |
| 비전투 선택지를 전투 진입 선택지로 변경 | `BATTLE_POSITION_MISMATCH` | -8 | -30 |
| `[전직보상]` 의미 누락 또는 잘못된 보상 연결 | `BATTLE_REWARD_MISMATCH` | -5 | -30 |
| 전투 제목 또는 전투 참조가 다른 전투를 가리킴 | `BATTLE_REFERENCE_MISMATCH` | -5 | -30 |

`BATTLE_WITHOUT_SOURCE_TAG` 또는 `BATTLE_MISSING`으로 특정 전투를 감점한 경우, 같은 전투의 개수 불일치는 중복 감점하지 않는다. 여러 전투 중 일부만 추가되거나 누락되어 개수 자체가 별도로 틀린 경우에는 실제 원인이 되는 전투별 오류를 우선 적용한다.

전투 표식의 태그 문구가 바뀐 경우 지문 영역과 전투 영역을 구분한다.

- 태그만 `[전투][전직보상]`에서 `[전투]`로 바뀌고 battle 자체는 올바르면 지문 영역의 의미 태그 감점과 전투 영역의 `BATTLE_REWARD_MISMATCH`를 적용한다.
- `[전투]`가 삭제되어 battle도 함께 누락되었다면 지문 영역의 의미 태그 감점과 전투 영역의 `BATTLE_MISSING`을 적용한다.

## 전개 순서 및 파생 데이터 정합성: 10점

| 오류 | 오류 코드 | 건당 감점 | 영역 최대 감점 |
|---|---|---:|---:|
| 사건의 상대 순서 변경 | `STORY_FLOW_CHANGED` | -5 | -10 |
| 원본에 없는 분기, 사건, 합류 결정 추가 | `STORY_FLOW_CHANGED` | -5 | -10 |
| popup 연결 누락 또는 잘못된 `nextPopupId` | `STORY_FLOW_CHANGED` | -3 | -10 |
| 파생 기획 데이터가 원본과 충돌 | `DERIVED_DATA_CONTRADICTS_SOURCE` | -3 | -10 |

선택지 또는 전투 오류 때문에 발생한 동일한 흐름 문제는 선택지·전투 영역에서 이미 감점했다면 이 영역에서 다시 감점하지 않는다. 이 영역은 사건 전체의 순서 변경, 원본에 없는 장면 추가, 잘못된 popup 연결처럼 독립적인 전개 훼손에 사용한다.

## 점수 등급

| 점수 | 등급 | 의미 |
|---|---|---|
| 100 | S | 원본과 완전히 일치하며 허용된 표시 차이만 존재 |
| 95~99 | A | 경미한 문구 또는 메타데이터 오류가 있으나 선택지·전투·전개는 보존 |
| 85~94 | B | 수정이 필요한 불일치가 있으나 전체 진행 구조는 대체로 보존 |
| 70~84 | C | 선택지, 전투 또는 전개에 명확한 포팅 오류가 존재 |
| 50~69 | D | 여러 핵심 구조가 원본과 다르며 재검토가 필요 |
| 0~49 | F | 원본 포팅으로 보기 어려울 정도의 중대한 불일치 |

### 등급 상한

핵심 구조 오류가 있는데 경미한 등급을 받는 것을 방지하기 위해 다음 상한을 적용한다.

- `CHOICE_ADDED`, `CHOICE_MISSING`, `CHOICE_FLOW_MISMATCH`가 하나라도 있으면 최고 등급은 `B`
- `BATTLE_WITHOUT_SOURCE_TAG`, `BATTLE_MISSING`이 하나라도 있으면 최고 등급은 `C`
- `STORY_FLOW_CHANGED`로 원본 분기 또는 사건 결과가 달라졌으면 최고 등급은 `C`

등급 상한은 점수 자체를 추가로 깎지 않는다. 숫자 점수는 배점표대로 계산하고, 표시 등급만 상한을 적용한다.

예:

```text
Score: 92/100
Grade: C
Grade cap reason: BATTLE_WITHOUT_SOURCE_TAG
```

## Chapter 전체 점수

Chapter 점수는 Episode별 점수의 단순 평균으로 계산한다.

```text
Chapter 점수 = 모든 Episode 점수의 합 / 평가한 Episode 수
```

- 소수점 첫째 자리까지 표시한다.
- Chapter 등급은 평균 점수 구간으로 결정한다.
- 한 Episode라도 `BATTLE_WITHOUT_SOURCE_TAG` 또는 `BATTLE_MISSING`이 있으면 Chapter 최고 등급은 `C`다.
- 한 Episode라도 선택지 추가·누락·흐름 변경이 있으면 Chapter 최고 등급은 `B`다.
- 평균 점수와 함께 Episode별 점수도 반드시 보고한다.

## 판정 기준

점수와 합격 여부는 별도로 기록한다.

- 점수는 불일치의 규모를 비교하기 위한 정량 지표다.
- 최종 점수가 80점 이하이면 점수 기준으로 탈락한다.
- 최종 점수가 81점 이상이어도 절대 탈락 기준에 해당하면 탈락한다.

### PASS

다음 조건을 모두 만족한다.

- 점수가 `81~100/100`이다.
- 절대 탈락 기준에 해당하지 않는다.

### FAIL_SCORE

다음 조건을 만족하면 점수 탈락이다.

- 점수가 `0~80/100`이다.
- 절대 탈락 기준에는 해당하지 않는다.

### FAIL_ABSOLUTE

다음 절대 탈락 기준 중 하나라도 해당하면 점수와 관계없이 탈락한다.

| 기준 ID | 절대 탈락 조건 | 이유 |
|---|---|---|
| `AF-PORT-01` | 원본 Episode에 대응하는 Planning JSON이 없음 | 포팅 결과 자체가 없음 |
| `AF-PORT-02` | Planning JSON이 존재하지 않거나 다른 Act의 원본을 참조함 | 평가 대상과 포팅 대상이 일치하지 않음 |
| `AF-CHOICE-01` | 원본에 없는 선택지가 추가됨 | 플레이어의 결정 구조가 원본과 달라짐 |
| `AF-CHOICE-02` | 원본 선택지가 누락되거나 목적지가 변경됨 | 원본 분기 및 진행 구조가 보존되지 않음 |
| `AF-BATTLE-01` | `[전투]` 표식이 없는데 battle이 생성됨 | 원본에 없는 핵심 게임플레이가 추가됨 |
| `AF-BATTLE-02` | `[전투]` 표식이 있는데 대응 battle이 없음 | 원본의 핵심 게임플레이가 누락됨 |

절대 탈락이 발생해도 가능한 범위에서 점수를 계산하고 영역별 오류를 모두 보고한다.

## 결과 보고 형식

```text
Episode:
Source:
Planning JSON:
Result: PASS | FAIL_SCORE | FAIL_ABSOLUTE
Score: 0~100/100
Grade: S | A | B | C | D | F
Grade cap reason: none | 오류 코드
Absolute failure: none | 절대 탈락 기준 ID

Errors:
- Code:
  Deduction:
  Source location:
  JSON location:
  Source value:
  JSON value:
  Reason:

Allowed differences:
- 줄바꿈 또는 popup 분할 차이

Score breakdown:
- Narration and semantic tags: 0~30/30
- Choices: 0~30/30
- Battles: 0~30/30
- Story flow and derived data: 0~10/10
```

오류가 없으면 `Errors: none`으로 기록한다. 줄바꿈 차이만 존재하면 `PASS`로 판정하고 `Allowed differences`에만 기록한다.

## 체크리스트

### 원문 검사

- `sourceEpisodeFile`이 올바른 원본을 가리키는가?
- 지문의 단어, 문장부호, 의미 태그가 그대로 보존되었는가?
- 줄바꿈 차이를 문구 변경으로 잘못 판정하지 않았는가?

### 선택지 검사

- 원본의 모든 `선택:` 문장이 JSON에 존재하는가?
- JSON의 모든 선택지가 원본에 실제로 존재하는가?
- 선택지 문구, 순서, 위치, 목적지가 원본과 같은가?

### 전투 검사

- 원본의 `[전투]` 및 `[전투][전직보상]` 개수와 JSON 전투 개수가 같은가?
- `[전투]`가 없는 Episode에 전투 데이터가 만들어지지 않았는가?
- `[전투]`가 있는 Episode에 대응 전투 데이터가 빠지지 않았는가?
- `[전직보상]` 의미가 포팅 과정에서 삭제되지 않았는가?
- 전투 선택지가 원본의 전투 위치에서 열리는가?

### 전개 및 점수 검사

- popup 분할 이후에도 사건 순서가 그대로인가?
- 파생 기획 필드가 원본에 없는 사건이나 확정 사실을 만들지 않았는가?
- 같은 원인을 여러 필드에서 중복 감점하지 않았는가?
- 영역별 감점이 해당 영역의 최대 배점을 넘지 않았는가?
- 최종 점수, 영역별 점수, 등급과 등급 상한 사유를 기록했는가?
