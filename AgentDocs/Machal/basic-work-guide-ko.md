# Machal 기본 작업 가이드

## 목적과 범위

이 문서는 ProjectBS에서 Machal과 작업할 때 에이전트가 따르는 기본 작업 방식을 정의한다.
사용자 또는 Task 요청이 `AgentDocs/Machal/README.md`를 지정한 경우에만 적용한다.

Task 고유 결정은 이 공통 가이드가 아니라 현재 Task 문서에 기록한다.

## 작업 전

1. 정확한 체크아웃과 프로젝트 루트를 확인한다.
2. `AgentDocs/Machal/README.md`가 지정한 필수 문서를 읽는다.
3. 작업 트리를 확인하고 관련 없는 추적, 미추적, 미스테이징 작업을 보존한다.
4. 제공된 모든 참고 경로를 확인한다. 누락된 경로를 비슷한 파일로 대체하지 말고 보고한다.
5. 데이터를 변경하기 전에 현재 런타임 원본, 작성 원본, 생성 결과의 위치를 구분한다.

## 작업 방식

1. 수정 전에 범위를 고정하고 소유 경로를 나열한다.
2. 독립적으로 검증 가능한 작은 단위로 작업한다.
3. 코드 작업은 가능한 경우 호출 가능한 진입점과 관찰 가능한 임시 `[PLACEHOLDER]` 로그를 먼저 만든다.
4. Placeholder 경로를 검증한 뒤 구현 단위를 한 번에 하나씩 교체한다.
5. 데이터 해석을 Passive View 밖에 둔다.
6. 클래스명, 에셋명, 스킬명, Effect명에서 문자열을 추론하기보다 구조화된 데이터와 명시적 카테고리를 우선한다.
7. 컴파일이나 일부 연결만 확인한 상태를 기능 완료로 보고하지 않는다.
8. 검사 및 Debug 출력은 완전하게 유지한다. 생략 또는 기본값 필터는 명시적으로 이름 붙인 플레이어 표시 경로에만 적용한다.

## 아키텍처와 경로 규칙

- 런타임 코드는 게임플레이 도메인 소유권으로 분류한다.
- 여러 도메인이 공유하는 Presentation 계약은 기존 `Assets/Scripts/Presentation/` 바로 아래에 둔다. Machal Presentation 작업을 위해 새 `Assets/Scripts/Core/` 경로를 만들지 않는다.
- 게임플레이 해석과 매핑은 `Assets/Scripts/Ability/` 같은 소유 도메인에 둔다.
- 정규화된 콘텐츠 데이터만을 위해 콘텐츠 도메인에 `Presentation/` 하위 폴더를 만들지 않는다. 데이터 타입은 소유 도메인의 기존 또는 계획된 `Data/` 하위 폴더에 두고 Resolver나 Builder 동작은 소유 경로 바로 아래에 둔다.
- 이 기능만을 위한 별도 `Resolvers/` 하위 폴더를 만들지 않는다. `EffectPresentationResolver`, `SkillPresentationResolver`처럼 역할이 드러나는 클래스명으로 구분한다.
- UI 컴포넌트와 프리팹 바인딩은 기존 Presentation/UI 구조를 따른다.
- 게임플레이 의미를 UI가 소유하게 만들지 않는다.
- 현재 Task가 마이그레이션을 명시적으로 소유하지 않으면 기존 콘텐츠나 레거시 경로를 재구성하지 않는다.

## 데이터와 에셋 규칙

- 현재 Task 문서에서 승인한 소스 및 에셋 경로만 사용한다.
- 새 기능 구현을 쉽게 만들기 위해 레거시 데이터를 수정하지 않는다.
- 이름으로 동작을 추론하지 않는다.
- 수치 단위는 런타임 코드를 확인한다. 비슷한 필드도 `0..1`, `0..100`처럼 다른 범위를 사용할 수 있다.
- 런타임 Resolver가 적용하지 않는 직렬화 Override나 Modifier를 임의로 적용하지 않는다.
- 여러 Effect를 각각의 의미 레코드로 유지한다.
- 플레이어 표시용 Localization 키 필드는 실제 Localization 소유 경로로 해석한다.
- 실패 사례를 구분한다. 표시 매핑이 없는 미승인 원본 게임플레이 Key는 생략하지만, 승인된 매핑 Key 또는 필수 이름/설명 Key가 누락되면 의도한 전체 Localization Key를 표시한다. 표시된 누락 Key는 디버깅 근거이며, 이를 임의 생성 문구나 구조화 수치에서 추론한 문장으로 대체하지 않는다.

## 검증

각 완료 단위에는 위험도에 맞는 다음 근거가 필요하다.

- 수정한 정확한 파일
- 필요한 경우 실제 호출 경로
- 데이터 원본과 구조화된 결과 비교
- 관련 컴파일 또는 자동 테스트
- UI 작업 시작 후 에셋 또는 프리팹 바인딩 확인
- `git diff --check`
- 남은 Fallback, 미지원, 수동 연결, 미검증 사례

## 문서화와 인계

범위가 정해진 각 작업 단위가 끝나면 현재 로그에 항목을 추가한다. 각 항목은 다음을 포함한다.

- 날짜와 상태
- 수행한 범위
- 생성하거나 수정한 파일
- 결정 사항
- 검증 근거
- 남은 작업
- 차단 요인 또는 위험
- 권장 다음 작업

나중 결과를 깔끔하게 보이게 만들기 위해 이전 로그를 다시 쓰지 않는다. 기존 결론이 바뀌면 정정 항목을 추가한다.

## Git

- 사용자가 명시적으로 요청하지 않으면 커밋하거나 푸시하지 않는다.
- 명시적으로 요청된 경로만 스테이징한다.
- 커밋이나 푸시 전에 스테이징 목록을 보여준다.
- 관련 없는 사용자 변경을 건드리지 않는다.
